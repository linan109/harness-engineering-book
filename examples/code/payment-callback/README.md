# 支付回调：把规格变成可验证的行为

对应《驾驭AI编程》第5章5.5节的教学主题。Python 3.10及以上，只用标准库，无网络、真实支付或外部服务。用SQLite内存库中的一条权益记录代替真正的会员服务。

## 契约

入口：`handle_callback(connection, body: bytes, signature: str, secret: bytes)`，返回`(状态码, 响应字典)`，不启动HTTP服务器。

使用`create_store()`创建的专用连接，调用时没有进行中的其他事务；本例不共享调用方事务或跨线程连接。`before_commit`是测试故障注入入口，不是支付业务参数。

- `body`为UTF-8 JSON对象，`event_id`、`order_id`、`status`为非空字符串，且解码后的字符串必须能严格编码为UTF-8（不接受孤立代理项）。签名为原始`body`字节的HMAC-SHA256十六进制值，不能先解析再重编码验签。示例密钥只用于本地练习。
- 先验签，无效返回403；已验签但格式无效返回400；订单不存在返回404。
- 本练习只实现`pending → paid`。新事件试图更新`paid`、`refunded`或`closed`订单，或传入非`paid`事件，返回409。退款和关闭只作为已有订单状态，不提供其处理器。
- 已成功处理的`event_id`携带完全相同的原始字节重试，返回200且`duplicate=True`；同ID换内容返回409。新ID重复通知同一已支付订单返回409，权益仍只有一份。不同JSON编码即使语义相同，也属于本教学契约的内容冲突。
- 状态更新、事件记录、权益记录必须一起提交。数据库语句或提交失败返回503，全部回滚；原事件可以重试。拒绝请求不记录为已成功事件。

## 运行与验收

从仓库根目录执行：

```sh
python examples/code/payment-callback/payment_callback.py
python -m unittest discover -s tests -p "test_examples*.py" -v
```

演示依次输出首次成功、重复成功，最后`memberships: 1`。测试覆盖伪造/篡改签名、坏输入、未知订单、重复与冲突事件、乱序状态，以及真实SQLite提交失败后的回滚和重试。

练习时可先按契约自行实现，再运行测试并对照`payment_callback.py`。测试通过只支持其覆盖到的本地行为。此例不包含支付金额、币种、商户归属、重放时效、密钥轮换、持久化运维及并发负载验证，不可直接用于生产。真实外部权益发放无法被SQLite事务撤回，需要另行设计事务消息或outbox及消费端幂等，不能把HTTP调用塞进事务就声称解决了一致性。
