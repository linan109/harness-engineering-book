# QA 独立测试 Prompt
> Independent QA Test Generation | 来源：《驾驭AI编程》第5章

## 使用场景

让独立会话依据需求和接口契约生成测试，减少实现思路对测试的影响。可以提供函数签名、输入输出结构和外部依赖契约，先不提供实现、实现者解释或实现会话生成的测试。

这是独立生成测试。书中“双翻译”指把代码反述为自然语言，再与原需求比较，见[代码反述Prompt](code-restatement.md)。两者可以配合，但不能互相代替。独立会话也可能共享错误假设，需要人工审查测试预期。

## 基础版本

```text
你是QA工程师。请根据以下材料独立设计行为测试，先不要阅读实现代码。

需求：[粘贴已确认需求]
接口契约：[函数签名/API、输入结构、输出结构、错误约定]
依赖契约：[可控制的外部服务、时钟、随机源及测试夹具]

1. 先列出需求与契约中缺失、冲突或含糊的信息，说明哪些用例因此受阻。
   不要自己决定缺字段、非法类型、金额精度或并发冲突的预期结果。
2. 对信息充分的部分，给出正常、边界和异常用例，每条标明契约依据、输入、
   期望输出及可观察副作用。不要根据猜测补规则，也不要测试内部实现步骤。
3. 区分可直接运行的测试与待确认的测试设计，列出未覆盖范围。
4. 固定时间、随机种子和外部返回值；需要集成环境的场景单列。
```

## 会员等级示例

```text
请独立生成测试，不阅读实现。

需求：累计消费满1000元为银卡，满5000元为金卡，满20000元为钻石卡，
否则为普通会员，取满足条件的最高等级。
接口：membership_level(total_cents: int) -> str
输入：非负整数，单位为分；bool、其他类型抛TypeError，负数抛ValueError。
输出："普通会员"、"银卡"、"金卡"或"钻石卡"。

覆盖零、各阈值及其上下1分、远高于最高阈值、负数和非法类型。
每条用例写明规则依据；如发现其他缺失信息先列未知，不发明预期。
```

## API接口示例：先发现契约缺口

```text
请独立设计POST /api/orders的测试，不阅读实现。

现有需求：
- JSON为{"user_id": string, "items": array, "coupon_code": string?}
- 成功返回201和含order_id、total_price、discount的订单详情
- 无效优惠券返回400，用户不存在返回404，库存不足返回409

先指出还缺少什么，至少检查items元素结构、价格与折扣来源、金额单位和精度、
空items/缺字段/类型错误的处理、多个错误的优先级及并发库存语义。
不要自行填成某个实现。先列待确认项及受影响测试；仅为已有充分契约的行为
设计用例。获得补充契约后再生成可执行测试。
```

## 使用技巧

- 用新会话或另一工具生成测试，提供必要契约，让测试能够调用真实接口；不要用“完全隔绝所有代码信息”阻断函数签名等必要输入。
- 人工核对预期值和业务规则，尤其是阈值、状态流转、错误优先级和副作用。独立生成不等于独立证明。
- 测试失败时默认修实现；若需求变更或测试本身有错，先说明依据，按已有授权或经确认后修改测试。不能为了绿灯降低断言。
