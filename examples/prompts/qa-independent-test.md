# QA 独立测试 Prompt
> Independent QA Test Generation — Separate the Judge from the Player | 来源：《驾驭AI编程》第5章

## 使用场景
- 用 AI 写完功能代码后，需要独立生成测试来验证正确性
- 实践"双翻译"验证法：需求分别翻译成代码和测试，两条路径独立交叉验证
- 防止 AI 写的测试和代码犯同一个错误（测试只看需求，不看实现）

## 基础版本

```
你是一个QA工程师。你只看到下面的需求描述，没有看到任何实现代码。
请根据需求写出完整的测试用例，包括：正常流程、边界条件、异常路径。
不要假设实现方式，只测试期望行为。
```

> 核心原则：写测试的 AI 只看需求，不看代码。具体的 prompt 措辞会随工具演进变化，但这条原则不变。

## 变体

### 带需求描述的完整版

实际使用时，把需求直接嵌入 prompt。

```
你是一个QA工程师。你只看到下面的需求描述，没有看到任何实现代码。

## 需求描述
用户会员等级计算规则：
- 累计消费满 1000 元升银卡
- 累计消费满 5000 元升金卡
- 累计消费满 20000 元升钻石卡
- 未达到 1000 元为普通会员

请根据需求写出完整的测试用例，包括：
1. 正常流程（每个等级至少一个典型值）
2. 边界条件（恰好等于阈值、差1元、超1元）
3. 异常路径（负数、零、超大数值、非数字输入）
不要假设实现方式，只测试期望行为。
```

### API 接口测试版

针对 API 需求生成独立测试。

```
你是一个QA工程师。你只看到下面的 API 需求描述，没有看到任何实现代码。

## API 需求
POST /api/orders
- 接收 JSON body: { "user_id": string, "items": array, "coupon_code": string? }
- 返回 201 + 订单详情（含 order_id, total_price, discount）
- 优惠券无效返回 400
- 用户不存在返回 404
- 库存不足返回 409

请生成完整的测试用例，包括：
1. 正常流程（单商品、多商品、带优惠券、不带优惠券）
2. 边界条件（空 items、单个 item、大量 items）
3. 异常路径（无效优惠券、不存在的用户、库存不足、字段缺失、类型错误）
4. 并发场景（同一商品同时被多人下单）
不要假设实现方式，只测试期望行为。
```

### 对抗性测试版

当你想让 AI 特别关注"容易骗过测试"的场景。

```
你是一个资深QA工程师，以发现隐藏 bug 著称。
你只看到下面的需求描述，没有看到任何实现代码。

请生成测试用例，特别关注以下陷阱：
1. 边界值：恰好等于阈值的情况（大于还是大于等于？）
2. 顺序依赖：操作顺序不同是否影响结果？
3. 状态残留：连续调用之间是否有状态泄漏？
4. 空值和默认值：未提供的字段用什么默认值？
5. 精度问题：浮点数计算是否有精度损失？

## 需求描述
[粘贴需求]
```

## 使用技巧

- **独立会话是关键**：不要让写代码的 AI 在同一个会话里写测试。AI 对需求的理解偏差会同时体现在代码和测试两边，导致"代码和测试犯的是同一个错误"。用新会话、新对话、或另一个 AI 工具来写测试。
- **你的时间花在审测试上**：AI 生成测试的速度远快于人写，所以让 AI 写、你来审是更高效的分工。审查重点：边界条件覆盖了吗？异常路径测了吗？安全相关的场景有没有漏？
- **搭配"不许改测试"铁律**：让 AI 实现代码时，明确告诉它"测试文件不允许修改"。否则 AI 遇到测试不过时会悄悄改测试用例直到通过，所有绿灯都是假的。
