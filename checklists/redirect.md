# 校准流程实操清单
> Redirect Checklist: When AI Goes Off Track | 来源：《驾驭AI编程》第6章 6.9节

AI走偏了怎么办？按这份清单走：先诊断错在哪层，再选对应的校准策略。校准最重要的不是怎么做，而是什么时候停。

---

### 诊断

- [ ] 判断错在哪层：代码层（一轮解决）/ 设计层（大范围重写）/ 需求层（从头来过）
- [ ] 连续2轮没解决 → 往上一层想

### 表达

- [ ] 具体：不是"不对"，是"哪里不对、要改成什么样"
- [ ] 一次一个：分轮校准，每轮确认后再提下一个
- [ ] 带上理由：说"为什么"，AI才不会在别处犯同样的错
- [ ] 约束范围：只改X，不要碰其他文件

### Debug

- [ ] 给上下文链，不要只丢一行报错
- [ ] 偶发bug → 让AI加日志，不要让AI直接修
- [ ] AI说"已修复" → 跑一遍验证

### 校准失灵的信号

- [ ] 修一个bug，出两个新bug → 回退重写
- [ ] AI开始重复之前的方案 → 换模型或开新对话
- [ ] 你已经看不懂代码了 → 让AI梳理全局逻辑
- [ ] 3轮未解决 → 强制评估"扔掉重来"

### 破解思路

- [ ] 开新对话：带代码现状 + 一句话需求 + 踩坑记录
- [ ] 换模型：成本几秒钟，40-50%概率一轮解决
- [ ] 自己动手：10行以内、清楚怎么改 → 直接改

### 团队

- [ ] 翻车记录维护在代码仓库（不是Wiki）
- [ ] 每条记录三字段：发生了什么、根因、新规则
- [ ] R→C闭环靠人的纪律，没有工具替你做
