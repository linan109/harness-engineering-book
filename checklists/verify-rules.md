# 验证规则：写给AI的纪律 + 写给自己的纪律
> Verification Rules: For AI and For Yourself | 来源：《驾驭AI编程》第5章 5.9节

方法再好，不执行等于零。两类规则：一类写给AI，设置一次自动生效；一类给自己，靠习惯养成。

---

### 写给AI的规则（直接粘贴到CLAUDE.md）

以下规则可以直接复制到你的项目CLAUDE.md中：

```
# 验证规则
- 禁止删除或修改已有测试用例，除非需求本身变更了测试预期
- 测试失败时，修代码，不许改测试
- 新增功能必须附带测试
- 代码必须能编译/运行，所有已有测试必须通过
- 执行结果截图或日志必须附在PR描述中
- 不得声称"已完成"而未提供运行验证的输出
```

### 对应检查清单

- [ ] CLAUDE.md中已包含"禁止删除或修改已有测试"规则
- [ ] CLAUDE.md中已包含"测试失败时修代码不许改测试"规则
- [ ] CLAUDE.md中已包含"新增功能必须附带测试"规则
- [ ] CLAUDE.md中已包含"代码必须能编译/运行"规则
- [ ] CLAUDE.md中已包含"执行结果必须附在PR描述中"规则
- [ ] CLAUDE.md中已包含"不得声称已完成而未提供验证输出"规则

---

### 写给自己的规则

- [ ] **看不懂就问。** 看不懂AI的代码时，直接问"这段代码在做什么？为什么用这种方式？"AI解释通了你学到新东西，解释不通你大概率抓住了bug
- [ ] **3次失败即回滚。** 连续修同一个bug三次未果，`git reset`或`git revert`，换思路重来
- [ ] **频繁提交，重构前必提交。** 每10-15分钟提交一次。每完成一个可验证的小步骤就commit。让AI做重构之前，一定先提交当前工作状态
