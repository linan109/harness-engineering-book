# 上下文自检

> 对应《驾驭AI编程》第4章。下面是排查线索，不是诊断“上下文腐烂”的计分表。

## 值得停下来检查的迹象

- 反复建议已否决的方案，却说不出原来为什么否决。
- 混用文件、分支、接口或不同阶段的需求。
- 把没有发生过的讨论、运行或验证说成已完成。
- 忘记当前约束，或沿用已经失效的旧决定。
- 回复方式明显漂移，无法准确说清当前目标和下一步。

这些现象也可能来自资料冲突、指令歧义、工具读取失败或模型本身的错误，不能只凭出现次数确定原因。让AI记住一个称呼等“暗号”也只能提供线索，记住暗号同样不能证明任务上下文完整。

## 先核对，再处理

| 核对什么 | 可以怎样做 |
|---|---|
| 当前目标是否一致 | 请AI简述目标、边界、验收条件，与原要求逐项比较 |
| 读到的是不是当前版本 | 检查工作目录、分支、文件内容和资料入口，不只听口头确认 |
| 材料是否相互矛盾 | 指定有效决定和被替代的旧版本，保留必要理由 |
| 关键背景是否缺失 | 补与本次任务直接相关的契约、复现和证据 |
| 历史是否已难以纠正 | 保存当前状态，开新会话从权威入口恢复 |

新会话需要的是有效状态，不是全部聊天记录。使用[HANDOFF模板](../templates/handoff/HANDOFF.md)记录目标、当前代码、未完成项、失败尝试和验证边界；切换后先核对事实，再继续工作。
