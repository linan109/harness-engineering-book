# CIVR：开始任务前的10个问题

> 对应《驾驭AI编程》第2章。根据任务风险使用，不要求每次填写整张表。

## C — 约束

- [ ] **范围清楚吗？** 这次要改什么，哪些文件、数据和系统不在授权范围内？
- [ ] **权限合适吗？** 工具和账号是否只获得任务所需权限？文字规则不能代替实际权限控制。
- [ ] **关键操作怎样把关？** 删除、迁移、发布和对外写入是否有明确授权、预演或恢复方案？

## I — 告知

- [ ] **目标能验收吗？** 用户最终应看到什么行为，哪些情况不在本次范围内？
- [ ] **背景够用吗？** 已提供当前实现、接口契约、必要业务规则和关键取舍吗？
- [ ] **资料有冲突吗？** 哪份是当前依据，哪些旧决定已经失效，哪些问题仍待确认？

## V — 验证

- [ ] **怎样证明做对了？** 选了与风险相称的检查，并覆盖关键边界和失败路径吗？
- [ ] **证据覆盖了什么？** 能区分测试通过、集成完成和实际用户流程可用吗？高风险结果由谁复核？

## R — 校准

- [ ] **偏离时怎样停下来？** 什么迹象说明继续尝试没有获得新信息，需要重新定位问题？
- [ ] **怎样恢复和交接？** 当前可恢复基线、未提交工作、已尝试方案和下一步能找得到吗？

小改动也要明确目标、边界和验证方式；涉及多人协作、敏感数据或不可逆操作时，再展开权限、交接和恢复细节。
