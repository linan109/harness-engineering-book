# 告知 Checklist

> 对应《驾驭AI编程》第4章。目标是让AI拿到当前任务需要的背景。

## 告诉它什么

- [ ] **目标与边界。** 期望行为、明确不做的事、验收条件。
- [ ] **业务隐性知识。** 新加入项目的人不知道、但会影响实现的规则。
- [ ] **当前事实。** 实际代码、接口、依赖版本、运行环境和可复现的问题。
- [ ] **关键决定。** 已选方案、理由及已否决方案；标明哪些旧决定被替代。
- [ ] **未知项。** 缺少的证据和仍需判断的问题，不把猜测写成已确认要求。

## 怎样提供

- [ ] 先给权威资料入口和当前任务，再按需读取细节，避免整库资料一次塞入。
- [ ] 用具体输入、期望输出、实际结果解释差异；日志去掉密钥和个人信息。
- [ ] 对容易歧义的任务，请AI复述理解，再与原要求核对。复述准确不等于实现正确。
- [ ] 让AI在重要结论旁标出文件或资料依据，方便发现读错版本和凭空补全。

## 任务进行中

- [ ] 需求、接口或分工变化后，更新当前依据，说明受影响的工作。
- [ ] 反复忘记决定、混用文件等是排查信号；先核对材料冲突、任务歧义和实际读取情况，见[上下文自检](context-health.md)。
- [ ] 若历史对话已难以纠正，用[交接模板](../templates/handoff/HANDOFF.md)保存有效状态，再开新会话。
- [ ] 规则和资料变更后检查对应工具的加载方式，不假设写入文件就会自动生效。
